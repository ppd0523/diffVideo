# 프리뷰 리소스 비교 — 2026-09-04

성능 목표 없이 각 방식을 한 번씩 측정한 관찰 결과다. 수치를 맞추기 위한 성능
수정·재측정 반복은 하지 않았다. 아래 수치는 이 PC와 합성 입력에 한정되며
다른 코덱·해상도·PC에서의 감소율을 보장하지 않는다.

## 조건

- Windows 11 x64, OS 빌드 26200
- AMD Ryzen AI 7 450 w/ Radeon 860M, 논리 프로세서 16개
- 전 구간이 움직이는 H.264 1920×1080 30fps 80초 영상 두 개와 MP3
- 캔버스 1920×1080, 각 영상 960×1080 Fill, 두 번째 영상 오프셋 1초
- MP3 오프셋 123ms, 볼륨 30%, 영상 오디오 각 100%, 공통 리미터
- 동일한 1000×640 WPF 진단 창, 타임라인 3초 진행 후 약 60초 측정
- 기존: 0.2.0의 FFmpeg 합성 rawvideo + 기존 오디오 미리듣기 코드 경로
- 변경: Windows MediaPlayer 두 개 + 화면 배치 + 버퍼형 공통 오디오 믹스
- 전체 앱 실행 파일끼리의 비교가 아니라 같은 진단 호스트에서 두 프리뷰 경로를 비교

## 결과

| 지표 | 기존 방식 | 개별 플레이어 | 변화 |
|---|---:|---:|---:|
| 평균 CPU, 전체 16논리코어 대비 | 3.487% | 0.214% | 93.9% 감소 |
| 평균 Working Set 합계 | 552.96 MiB | 481.27 MiB | 13.0% 감소 |
| 최대 Working Set 합계 | 556.92 MiB | 543.97 MiB | 2.3% 감소 |
| 평균 Private Bytes 합계 | 496.73 MiB | 461.37 MiB | 7.1% 감소 |
| 프로세스 귀속 GPU 엔진 중 최대 사용률의 평균 | 2.35% | 9.46% | 7.11%p 증가 |
| 리소스 샘플 수 | 28 | 29 | — |

CPU와 메모리는 앱과 직접 하위 FFmpeg 프로세스의 합계다. Working Set에는 공유
페이지가 중복 집계될 수 있다. GPU 지표는 가장 바쁜 엔진을 고르므로 전체 GPU
사용량·GPU 메모리·전력 소비와 같지 않다. CPU 사용량 감소를 전체 리소스나 전력의
동일 비율 감소로 해석하면 안 된다. 다른 PC에서는 원본 디코더 대체 경로를 사용할
수 있으며, 위 비교의 새 방식은 두 영상 모두 Windows MediaPlayer를 사용했다.
